\chapter*{Resumen}
\addcontentsline{toc}{chapter}{Resumen}

EcoBrief Bolivia es una plataforma que utiliza inteligencia artificial de forma responsable para reducir el desperdicio digital informativo. El sistema recolecta noticias de medios bolivianos, elimina duplicados, prioriza el contenido relevante y genera resumenes claros para que las personas no tengan que abrir multiples paginas, leer la misma historia varias veces o consumir datos innecesarios.

La propuesta no busca crear mas contenido sino reducir el ruido digital. EcoBrief transforma un flujo disperso de noticias, redes sociales y fuentes digitales en informacion breve, priorizada y medible.

El prototipo ya cuenta con \textit{web scraping} real de medios locales, clasificacion por categorias, ranking de prioridad, resumenes con IA, deduplicacion historica, base de datos PostgreSQL, frontend web y pagina de impacto. El sistema esta desplegado en un VPS de Hostinger y accesible publicamente en https://briefs.ecobriefbolivia.online/.

\chapter{Introduccion}

\section{Contexto y motivacion}

En la era digital, el acceso a la informacion nunca ha sido tan amplio ni tan fragmentado. Para una persona en Bolivia, informarse sobre la actualidad nacional implica revisar multiples medios de comunicacion, abrir decenas de pestanas del navegador, comparar titulares, buscar contexto en redes sociales y descartar noticias repetidas. Este proceso genera un volumen significativo de desperdicio digital.

El \textbf{desperdicio digital informativo} se manifiesta en tiempo perdido revisando la misma noticia en distintos sitios, datos moviles consumidos al cargar paginas completas con publicidad y exposicion a informacion fragmentada o sin fuente verificable en redes sociales.

Esta problematica se alinea con los principios de \textbf{Green Tech}: promover un uso mas eficiente, responsable y sostenible de la tecnologia, la IA, el \textit{cloud}, los datos y los procesos internos.

\section{Objetivos}

\textbf{Objetivo general:} Desarrollar una plataforma de IA responsable que reduzca el desperdicio digital informativo mediante recoleccion, deduplicacion, clasificacion y resumen eficiente de noticias bolivianas.

\textbf{Objetivos especificos:}
\begin{enumerate}[nosep]
    \item Recolectar automaticamente noticias de fuentes bolivianas mediante \textit{web scraping}.
    \item Implementar deduplicacion multinivel (URL, titulo, huella de contenido).
    \item Clasificar y priorizar noticias por categoria y relevancia.
    \item Generar resumenes con IA aplicando filtrado, deduplicacion y ranking previos.
    \item Medir y visualizar el impacto mediante metricas cuantificables.
    \item Distribuir informacion personalizada segun preferencias del usuario.
\end{enumerate}

\section{Arquitectura del sistema}

El sistema se compone de frontend React, backend FastAPI, base de datos PostgreSQL y servicios de scraping, procesamiento, distribucion y tareas que se ejecutan repetidamente (cron jobs).

\subsection{Frontend}

Vistas: Home (noticias destacadas), Noticias (listado completo), Detalle (articulo original y resumen), Impacto (metricas Green Tech), Suscripcion (preferencias).

\subsection{Backend API}

El backend es el coraz\'on de EcoBrief. Construido con \textbf{FastAPI} sobre Python as\'incrono, orquesta todo el pipeline de recolecci\'on, procesamiento y distribuci\'on. Expone una API REST que sirve como puente entre el frontend y la l\'ogica del sistema.

Sus responsabilidades principales incluyen:

\begin{itemize}[nosep]
    \item Ejecutar el pipeline completo de noticias (scraping, dedup., clasificaci\'on, ranking, resumen) bajo demanda o mediante programaci\'on horaria.
    \item Servir datos estructurados al frontend a trav\'es de endpoints ligeros.
    \item Gestionar suscriptores, preferencias y la distribuci\'on personalizada de res\'umenes.
    \item Calcular y exponer m\'etricas de impacto Green Tech en tiempo real.
    \item Validar solicitudes sensibles mediante una clave API (\texttt{X-API-Key}).
\end{itemize}

El cliente de inteligencia artificial est\'a abstra\'ido detr\'as de una capa que permite cambiar de proveedor (Groq, OpenAI, GitHub Models) sin modificar el resto del sistema. La operaci\'on cr\'itica de generaci\'on de res\'umenes se activa a trav\'es de \texttt{POST /trigger/summary}, permitiendo controlar cu\'ando se consume el proveedor IA.


\section{Pipeline de procesamiento}

El flujo de EcoBrief sigue un proceso secuencial dise\~nado para minimizar el procesamiento innecesario antes de usar inteligencia artificial. Se organiza en cuatro fases:

\paragraph{Recolecci\'on}
\begin{itemize}[nosep]
    \item \textbf{Inicio:} Se activa una corrida, manualmente o mediante el programador horario (\textit{scheduler}).
    \item \textbf{Cach\'e:} Se verifican res\'umenes recientes v\'alidos; de existir, se reutilizan sin ejecutar el pipeline completo.
    \item \textbf{Scraping:} Se recolectan noticias desde las fuentes configuradas.
\end{itemize}

\paragraph{Filtrado y deduplicaci\'on}
\begin{itemize}[nosep]
    \item \textbf{Filtro:} Se descartan art\'iculos sin contenido suficiente.
    \item \textbf{Deduplicaci\'on en lote:} Se eliminan duplicados dentro de la corrida por URL y t\'itulo normalizado.
\end{itemize}

\paragraph{Clasificaci\'on y priorizaci\'on}
\begin{itemize}[nosep]
    \item \textbf{Clasificaci\'on:} Cada art\'iculo se asigna a una categor\'ia (econom\'ia, pol\'itica, deportes, etc.).
    \item \textbf{Ranking:} Puntaje de prioridad seg\'un recencia, confiabilidad, calidad e impacto nacional.
    \item \textbf{Persistencia:} Los art\'iculos se almacenan en PostgreSQL.
    \item \textbf{Huella hist\'orica:} Se calcula un \textit{fingerprint} SHA-256 por art\'iculo para detectar duplicados entre corridas.
\end{itemize}

\paragraph{Generaci\'on y distribuci\'on}
\begin{itemize}[nosep]
    \item \textbf{Selecci\'on:} Los mejores candidatos \'unicos se env\'ian al modelo de IA.
    \item \textbf{Resumen:} El LLM genera un resumen breve para cada candidato.
    \item \textbf{Normalizaci\'on:} Se reescriben los res\'umenes para mantener coherencia de estilo.
    \item \textbf{M\'etricas:} Se guardan resultados y se calculan las m\'etricas de impacto.
    \item \textbf{Entrega:} Se prepara el env\'io seg\'un las preferencias del suscriptor.
\end{itemize}

\subsection{Web Scraping}

El sistema utiliza \texttt{httpx} junto con \texttt{BeautifulSoup} y \texttt{lxml} para realizar \textit{web scraping} de fuentes bolivianas. Cada fuente est\'a definida en \texttt{config/sources.yaml} con selectores CSS configurables (selector de art\'iculo, t\'itulo, URL, fecha, imagen y cuerpo). Cuando una fuente cambia su estructura HTML, el sistema cuenta con un mecanismo de \textit{fallback} gen\'erico que extrae todos los enlaces del documento y filtra aquellos que parecen art\'iculos period\'isticos, permitiendo seguir recolectando incluso si los selectores originales no coinciden.

\subsection{Deduplicacion}

EcoBrief implementa tres niveles de deduplicaci\'on a lo largo del pipeline:

\begin{enumerate}[nosep]
    \item \textbf{Deduplicaci\'on por URL:} Cada URL se convierte en un hash MD5. Esto evita guardar o procesar el mismo enlace repetido dentro de una misma corrida.
    \item \textbf{Deduplicaci\'on por t\'itulo:} Los t\'itulos se normalizan (min\'usculas, sin acentos, sin signos) y se comparan con \texttt{SequenceMatcher}. Si la similitud supera 0.85, se considera duplicado y se conserva la versi\'on m\'as reciente.
    \item \textbf{Deduplicaci\'on hist\'orica por huella:} Se calcula una huella (\textit{fingerprint}) SHA-256 basada en la categor\'ia, el t\'itulo normalizado y un fragmento del contenido. Esto permite agrupar noticias equivalentes a trav\'es de distintas corridas, aunque tengan URL y fuente diferentes.
\end{enumerate}

Los duplicados no se eliminan definitivamente; se marcan para auditor\'ia y se excluyen de los candidatos a resumen, preservando la trazabilidad.

\subsection{Clasificacion}

Cada noticia se clasifica en una de cinco categor\'ias mediante un sistema de reglas ponderadas configurable en \texttt{config/classification.yaml}:

\begin{itemize}[nosep]
    \item \textbf{Econom\'ia:} Finanzas, d\'olar, tipo de cambio, BCB, inflaci\'on, hidrocarburos.
    \item \textbf{Pol\'itica:} Gobierno, presidente, elecciones, Asamblea, leyes, partidos.
    \item \textbf{Deportes:} F\'utbol, clubes, torneos, selecci\'on boliviana, resultados.
    \item \textbf{Tecnolog\'ia:} IA, software, internet, ciberseguridad, telecomunicaciones.
    \item \textbf{Entretenimiento:} Cine, m\'usica, televisi\'on, festivales, far\'andula.
\end{itemize}

El clasificador asigna puntuaci\'on a cada categor\'ia ponderando cuatro campos del art\'iculo:
\begin{itemize}[nosep]
    \item T\'itulo ($\times 3.0$)
    \item Descripci\'on ($\times 2.0$)
    \item Contenido ($\times 1.0$)
    \item Categor\'ia de la fuente ($\times 2.5$)
\end{itemize}

Si la diferencia entre la primera y segunda categor\'ia es menor a 2.0 puntos, o la confianza es baja ($<0.62$), el sistema puede recurrir a un LLM como fallback para reclasificar el art\'iculo.

Adicionalmente, el sistema aplica penalizaciones por contenido ausente (-25), contenido muy corto (-15), descripci\'on duplicada (-20), fecha faltante (-10), fuente desconocida (-8), confianza baja de categor\'ia (-10) y noticias internacionales sin contexto boliviano (-20).

El puntaje final se calcula como:

\begin{equation}
P = \sum_{f} w_f \cdot s_f - \text{penalizaciones}
\end{equation}

Donde $w_f$ es el peso del factor y $s_f$ su puntuaci\'on normalizada. El resultado se acota entre 0 y 100.

El objetivo no es resumir todo, sino resumir lo m\'as relevante.

\section{Eficiencia en el uso de IA}

La inteligencia artificial se emplea en dos fases del pipeline: clasificaci\'on de art\'iculos (solo como fallback ante casos ambiguos) y generaci\'on de res\'umenes. Para minimizar el costo operativo y la latencia, el sistema aplica las siguientes estrategias antes de invocar cualquier modelo:

\begin{table}[H]
\centering
\begin{tabular}{lp{10cm}}
\toprule
\textbf{Estrategia} & \textbf{Descripci\'on} \\
\midrule
Filtrar antes de IA  & Se descartan art\'iculos sin contenido suficiente o con metadatos incompletos antes de cualquier procesamiento. \\
\midrule
Deduplicar antes de IA & Se eliminan duplicados por URL y t\'itulo dentro del lote, evitando enviar la misma noticia al modelo m\'as de una vez. \\
\midrule
Rankear antes de IA  & Solo los art\'iculos mejor puntuados por el ranking de relevancia son candidatos a resumen. \\
\midrule
Limitar por categor\'ia & Se establece un m\'aximo de candidatos por categor\'ia para distribuir el presupuesto de c\'omputo entre todas las \'areas tem\'aticas. \\
\midrule
Cachear res\'umenes  & Los res\'umenes ya generados se reutilizan si el art\'iculo original no ha cambiado, evitando reprocesar contenido ya sintetizado. \\
\midrule
Control de duplicados & Se verifica que no exista un resumen equivalente en la misma corrida antes de generar uno nuevo. \\
\bottomrule
\end{tabular}
\caption{Estrategias de eficiencia en el uso de IA}
\end{table}

\section{Formulas de impacto}

Las estimaciones se derivan de tres calculos conservadores. Se define $R$ como el total de noticias recolectadas y $B$ como los briefs generados:

\paragraph{Paginas evitadas.} Diferencia entre lo recolectado y lo sintetizado:
\begin{equation}
P_{\text{evitadas}} = R - B = 110 - 39 = 71
\end{equation}

\paragraph{Tiempo de lectura ahorrado.} Estimando 30 segundos por pagina evitada:
\begin{equation}
M_{\text{ahorrados}} = P_{\text{evitadas}} \times 0.5 = 71 \times 0.5 = 35.5\text{ min}
\end{equation}

\paragraph{Tasa de reduccion del flujo.} Proporcion de contenido descartado respecto al total recolectado:
\begin{equation}
T_{\text{reduccion}} = 1 - \frac{B}{R} = 1 - \frac{39}{110} = 0.646 = 64.6\%
\end{equation}

    \item Clasificacion, ranking y deduplicacion.
    \item Resumenes con Groq/OpenAI/GitHub Models.
    \item Frontend React + Vite.
    \item Panel de metricas Green Tech.
    \item Pruebas automatizadas (pytest).
\end{itemize}

\section{Tecnologias}

Backend: Python 3.11, FastAPI. Frontend: React 18, Vite, TypeScript. BD: PostgreSQL 16, SQLAlchemy. Scraping: httpx, BeautifulSoup4. IA: Groq/OpenAI/GitHub. Infra: Docker, Hostinger VPS.

\section{Roadmap}

El MVP actual es funcional, pero existen funcionalidades pendientes de implementar. Se dividen en tres horizontes segun su prioridad:

\textbf{Comprometido (corto plazo):} backfill de fingerprints, exponer duplicados historicos, mostrar coberturas agrupadas por historia, mejorar historial de metricas.

\textbf{Planificado (mediano plazo):} medicion real de bytes descargados, activar Telegram/WhatsApp en produccion, dashboard historico por usuario, integrar boletines estatales como fuentes.

\textbf{Aspiracional (largo plazo):} deteccion por entidades, planes de suscripcion, panel institucional, monitoreo automatico de cambios en fuentes.

\chapter*{Conclusiones}
\addcontentsline{toc}{chapter}{Conclusiones}

El proyecto EcoBrief Bolivia se presento como una solucion al problema del exceso de informacion redundante en el ecosistema de noticias boliviano, con un enfoque Green Tech que prioriza la eficiencia, la reduccion del consumo digital y el uso responsable de inteligencia artificial.

\section*{Resumen de resultados}

El sistema fue desarrollado, desplegado y probado con fuentes reales de noticias bolivianas. En su corrida del 15 de junio de 2026, proceso 174 noticias y las redujo a 39 briefs priorizados, logrando una tasa de reduccion del 78\,\%. Esto se tradujo en 135 paginas evitadas y un ahorro estimado de 67.5 minutos de lectura por corrida.

\section*{Logros alcanzados}

\begin{enumerate}[nosep]
    \item \textbf{Alineacion Green Tech demostrada:} El proyecto reduce la navegacion innecesaria, la duplicacion de contenido, el consumo de datos y el procesamiento de IA redundante. Las metricas del 15 de junio confirman una reduccion del flujo superior al 78\,\%.
    \item \textbf{Prototipo funcional desplegado:} Aplicacion completa con backend FastAPI, frontend React con Vite, base de datos PostgreSQL, panel de metricas Green Tech y canales de distribucion, desplegada en un VPS de Hostinger con dominio propio.
    \item \textbf{Arquitectura modular y eficiente:} El diseno permite cambiar de proveedor de IA (Groq, OpenAI, GitHub Models), agregar nuevas fuentes y escalar componentes de forma independiente.
    \item \textbf{Bajo costo operativo:} La plataforma puede operar con un costo anual reducido, utilizando free tiers de IA, canales gratuitos como Telegram y un solo VPS como infraestructura.
    \item \textbf{IA responsable:} Filtrar, deduplicar y rankear antes de invocar al modelo reduce las llamadas IA. El cache evita reprocesar contenido ya resumido.
    \item \textbf{Impacto medible:} Cada corrida del pipeline produce metricas cuantificables que se muestran en el panel de impacto en tiempo real.
\end{enumerate}

\section*{Trabajo futuro}

A corto plazo, se implementará Umami a través de la infraestructura de Dokploy como la solución principal para la analítica web. A mediano plazo se activaran la distribusion por Telegram y WhatsApp en produccion. A largo plazo se explorara deteccion de informacion por entidades ejecutivas y gubernamentales del estado Boliviano, planes de suscripcion con precios accesibles.

\section*{Mensaje final}

EcoBrief Bolivia convierte un problema cotidiano ---el exceso de informacion redundante--- en una solucion Green Tech concreta, funcional y medible. Este proyecto, desarrollado por \textbf{Raquel Auza} (Digital-Academy) y \textbf{Josoe Ichuta} (Ingenieria), representa una apuesta por informacion esencial, inteligencia artificial responsable y eficiencia digital desde Bolivia.
